# Веб-журнал и нормоконтроль

Код: `apps/verification/journal.py` (выборка и выгрузка),
`apps/verification/api_journal.py` (API), `frontend/src/components/` (экраны).

## Журнал

Журнал — не таблица в базе, а **выборка поверок**. Отдельной сущности
«строка журнала» нет: всё, что в ней показывается, выводится из поверки,
протокола и результатов расчёта.

`GET /api/journal/` — постранично, с фильтрами:

| Параметр | Что делает |
|---|---|
| `q` | заводской номер, тип СИ, адрес, владелец |
| `date_from`, `date_to` | диапазон дат поверки |
| `suitable` | пригодно / непригодно |
| `status`, `protocol_status` | состояние поверки и протокола |
| `needs_review` | ждут сверки распознанного |
| `verifier`, `family` | по поверителю и семейству СИ |

`needs_review` вынесен на поверку отдельным индексируемым полем, а не ищется
внутри JSON: фильтр по JSON не работает на SQLite и медленно работает на
Postgres, а журналом пользуются каждый день.

## Выгрузка

`GET /api/journal/export/` отдаёт `.xlsx` **формата ФИФ ОЕИ** — те же 49
колонок и те же заголовки, что в прежнем журнале (они лежат в
`fixtures/journal_columns.json`, вынуты из рабочего файла). Фильтры те же,
что у списка, поэтому выгрузить можно ровно то, что видно на экране.

Соответствие колонок — в `journal.COLUMN_MAP`. Две вещи выглядят странно, но
воспроизведены намеренно, потому что так сложилось у вас:

- **адрес поверки идёт в графу «Владелец СИ»** (колонка 32);
- собственник — в отдельную графу «Собственник» (колонка 47).

Файл собирается с нуля через `openpyxl`: старый шаблон не открывается и не
правится, поэтому слетать нечему. Порядок строк — по возрастанию даты
поверки: журнал читается как хронология.

## Нормоконтроль

Экран показывает области нумерации (серия + поверитель + год) и что в каждой
происходит: сколько черновиков, сколько пронумеровано, сколько подписано,
до какого номера запечатано.

Главное правило — **сначала предпросмотр, потом применение**:

```
POST /api/normocontrol/scopes/{id}/preview/   что изменится, ничего не трогая
POST /api/normocontrol/scopes/{id}/assign/    применить пересчёт
POST /api/normocontrol/sign/                  подписать пачку протоколов
```

Кнопка «Пересчитать номера» в интерфейсе появляется только после
предпросмотра. Метролог видит построчно, какой протокол какой номер получит
и что сдвинется, — и лишь тогда нажимает.

Подпись пачкой не падает целиком из-за одного протокола: что не подписалось,
возвращается списком с причиной. Право подписи проверяет доменный слой —
аттестация должна действовать на дату поверки, не на сегодня.

`chronology_breaks` — самопроверка: пары протоколов, где номер идёт вразрез
со временем поверки. В норме список пуст. Непустой — это либо вставки вне
очереди (у них заполнена причина), либо ошибка, которую надо разобрать.

## Посмотреть живьём

```bash
cd backend
DJANGO_SETTINGS_MODULE=config.settings.local_sqlite python manage.py migrate
DJANGO_SETTINGS_MODULE=config.settings.local_sqlite python manage.py seed_catalog
DJANGO_SETTINGS_MODULE=config.settings.local_sqlite python manage.py seed_demo
DJANGO_SETTINGS_MODULE=config.settings.local_sqlite python manage.py runserver

cd ../frontend && npm install && npm run dev
```
