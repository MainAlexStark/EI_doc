# Аттестация испытательного оборудования

Холодильники, термостаты, сушильные шкафы, климатические камеры — ГОСТ Р 8.568-2017.
Код: `backend/apps/equipment`, экран — вкладка «Аттестация ИО» (`frontend/src/components/Attestations.tsx`).

## Почему отдельно от поверки

Протокол аттестации «нелинейный»: у каждого вида оборудования и каждой методики свои точки, режимы,
формулы, допуски и вид самого протокола. Поэтому в коде нет ни жёстких формул, ни жёсткого шаблона: всё это —
**план**, который ассистент собирает из документов, а EI_doc проверяет и исполняет.

| Что | Кто |
|---|---|
| **План**: точки и группы, режимы и их параметры, характеристики с формулами-выражениями, допуски с источником, каркас протокола | ассистент — из примера протокола, прошлой аттестации этого ИО, программы/методики и РЭ; **метролог проверяет** |
| **Сверка формул с примером** | EI_doc: прогоняет формулы на числах примера и сравнивает с напечатанными результатами |
| **Измерения и условия** | только человек, на экране |
| **Расчёт, соответствие, заключение, номер** | EI_doc (`calc.py`, `expr.py`, `layout.py`, `service.py`) |

Ассистент не может передать измерения или условия: `ei_attestation_propose` отказывает, `clean_plan`
не принимает ключи `measurements/readings/results/values`. Числа примера идут только в сверку и не
сохраняются (в карточке остаётся отчёт: «в примере / посчитано / сходится»).

> Почему так строго: в образце (протокол № 1886/2026) все 70 отсчётов во встроенной таблице Excel
> получены формулой `=ROUND(RAND()*…)` — это не измерения. Новый порядок такой протокол выпустить не даст.

## План (`calc.clean_plan`)

```json
{
  "equipment_kind": "Камера климатическая", "program": "…", "documents": ["…"],
  "quantity": "температура", "unit": "°С", "repeats": 3,
  "points": [
    {"key": "A", "label": "верх", "groups": ["corners"]},
    {"key": "B", "label": "низ", "groups": ["corners"]},
    {"key": "C", "label": "центр", "role": "control"}
  ],
  "modes": [
    {"key": "cold", "label": "−20 °С", "setpoint": "-20", "params": {"tol": "2"}},
    {"key": "hot",  "label": "+60 °С", "setpoint": "60",  "params": {"tol": "1.5"}}
  ],
  "characteristics": [
    {"key": "reached", "label": "Достигнутое значение", "expr": "mean(all)", "text": "Т = Σt/n",
     "tolerance": {"kind": "range", "min": "setpoint - tol", "max": "setpoint + tol"}, "source": "программа, п. 7.2"},
    {"key": "dev_point", "label": "Отклонение в точке", "per": "point", "group": "corners",
     "expr": "mean(x) - setpoint", "tolerance": {"kind": "abs", "limit": "tol"}, "source": "п. 7.3"},
    {"key": "uneven", "label": "Неравномерность", "expr": "max(abs(dev_point))", "decimals": 1}
  ],
  "conditions": [{"key": "temperature", "label": "Температура окружающего воздуха", "unit": "°С"}],
  "procedure": ["…"], "purpose": "…", "periodicity": "один раз в год",
  "document": {"header": ["…"], "title": "Протокол {{kind}} аттестации …", "subtitle": "№ {{number}} от {{protocol_date}}"},
  "conclusion": {"ok": "… {{who}} соответствует …{{purpose_tail}}.", "fail": "… {{who}} не соответствует: {{failed}}."},
  "layout": [ … ]
}
```

- **Группы точек**: `all`, `volume`, `control` есть всегда, свои — через `groups`.
- **Параметры режима** (`params`) — числа, которые различаются по режимам (свой допуск, своя скорость…).
- **Допуск**: `range{min,max}` | `abs{limit}` | `none`; границы — число или выражение от `setpoint` и
  параметров. Сравнение — по значению, округлённому до `decimals`, как в протоколе. Без `source` не принимается.
- `per: "point"` — характеристика считается по каждой точке группы (`x` — отсчёты точки); дальше по плану
  её ключ — ряд значений (`max(abs(dev_point))`).

## Формулы (`expr.py`)

Формула — выражение, которое пишет ассистент по методике или примеру. Считает EI_doc своим интерпретатором
(разбор `ast` с белым списком узлов, арифметика Decimal) — код от модели не выполняется.

- Числа, `+ − * / ^`, скобки.
- Имена: группы точек, `setpoint`, `display` (показание индикатора ИО — вносит человек), `n`, `repeats`,
  параметры режима, ключи характеристик выше по списку.
- Функции: `mean min max sum count range std means abs sqrt round`, `point("ключ")`.
- Группа в арифметике — все её отсчёты; ряд с числом — поэлементно; `means(группа)` — ряд средних по точкам.
- `round(x, n)` — чтобы повторить промежуточные округления примера (как `ROUND` в Excel).

Готовые формулы (`calc.PRESETS`: `mean_all`, `deviation_from_setpoint`, `amplitude_control`, `variation_*`,
`gradient`…) — только подсказка: на них можно сослаться `preset`, но ограничения нет.

План прогоняется на пробных данных ещё при проверке — формула, дающая ряд вместо числа, ссылающаяся на
пустую группу или неизвестное имя, не пройдёт.

## Сверка с примером (`calc.check_example`, инструмент `ei_attestation_check`)

Если в примере есть и отсчёты, и результаты, ассистент обязан прогнать план на них:
`example{source, modes: {режим: {display?, readings: {точка: […]}, expected: {характеристика: "0,52" | {точка: …}}}}}`.
Совпадение — в пределах единицы последнего напечатанного знака. Не сошлось — ассистент ищет причину в
документе (какие точки, порядок округления, знак), подгонять без объяснения запрещено. Отчёт сверки
хранится в карточке (`plan_check`), метролог видит его в плане; после правки плана помечается «устарела».
Формулы образца 1886/2026 сходятся до 1e-4.

## Каркас протокола (`layout.py`)

Вид протокола — тоже из примера: `layout` — список блоков.

- обычные блоки документа: `heading paragraph fields table list signatures pagebreak spacer` с подстановками
  `{{…}}` в тексте и ячейках;
- блоки-данные: `commission equipment_info checked conditions documents instruments procedure readings
  results conclusion signatures`; `results{columns: [label, formula, value, tolerance, verdict]}`;
- `per_mode{blocks}` — повторить для каждого режима (внутри режим — `_`);
- `"if": "путь"` — блок выводится, только если значение непустое.

Подстановки: `equipment.*`, `number`, `protocol_date`, `performed_on`, `kind`, `program`, `purpose`,
`periodicity`, `quantity`/`Quantity`, `unit`, `verdict`, `conclusion`, `conditions.<ключ>`, `texts.<ключ>`,
`mode.<режим>.label|setpoint|display|index|<параметр>`, `result.<режим>.<характеристика>[.<точка>]` с
`|tolerance|verdict|formula|label`, `mean.<режим>.<точка>`, `reading.<режим>.<точка>.<№>`.
Неизвестная подстановка — ошибка проверки плана, а не пустое место в протоколе.
Без `layout` — стандартный вид (по образцу 1886/2026).

## Жизненный цикл

1. **Карточка + план.** Ассистент → карточка в чате → «Подтвердить» (или вручную: «Новая аттестация» из
   программы-заготовки). План, заведённый метрологом, считается проверенным; заведённый поверителем — ждёт
   проверки. Любая правка плана снимает отметку о проверке.
2. **Измерения** — сетка точки × повторы по каждому режиму, дата, условия. Можно вставить ряд из Excel.
3. **Расчёт** — сразу, когда сетка полная.
4. **Подпись** (метролог/руководитель). Не даст подписать, если: план не проверен; сетка не полная; нет
   условий или даты; дата протокола в будущем или раньше измерений; нет председателя комиссии; у СИ нет
   срока поверки или он истёк к дате измерений. Номер `N/ГГГГ` — из `AttestationCounter` (стартовое
   значение года выставляется в админке, чтобы продолжить бумажную нумерацию). Подписанный протокол
   неизменяем: хранится снимок содержимого и его SHA-256, Word/PDF собираются из снимка.

## Протокол

Каркас из плана → блоки `apps.assistant.documents` → тот же движок, что у ассистента: Word (python-docx)
и PDF (Typst). Неподписанный — с водяным знаком «ЧЕРНОВИК».

## API

`GET/POST /api/attestations/` · `GET/PATCH /api/attestations/<id>/` · `PUT …/<id>/measurements/` ·
`POST …/<id>/approve-plan/` · `POST …/<id>/sign/ {protocol_date}` · `GET …/<id>/protocol.docx|pdf` ·
`GET /api/attestations/programs/`.

## Дальше

- Программы аттестации компании загрузить в «Программы аттестации» (админка) и в файлы ассистента;
  заготовка «Холодильники фармацевтические» снята с образца и помечена «ждёт проверки метролога».
- Импорт файла регистратора (логгера) вместо ручной сетки — значения из файла прибора, не от модели.
- Несколько величин в одной аттестации (температура и влажность одновременно) — сейчас одна величина на план.
