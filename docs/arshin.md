# Отправка результатов поверки в Аршин

Код: `backend/apps/arshin/submission.py`, API — `apps/arshin/api.py`,
экран — «Журнал → Нумерация и Аршин → Отправка в Аршин».

## Путь протокола

```
подписан ──► в пакете ──► отправлен ──► опубликован (номер записи ФИФ)
                │              │
                └─ отменён ────┴─ отклонён ──► снова в очереди
```

1. **Очередь.** Подписанные протоколы, которых нет ни в одном действующем
   пакете. Для каждого видно, чего не хватает ФИФ: номер типа в Госреестре,
   заводской номер, методика, эталоны, дата следующей поверки у годного,
   причины у непригодного, шифр знака поверки организации.
2. **Пакет.** Готовые протоколы собираются в XML (`<application>` с одной
   записью `<result>` на протокол), файл хранится с SHA-256. Неготовые в пакет
   не попадают и возвращаются с причинами — пакет из-за одного не падает.
3. **Загрузка.** XML скачивается и загружается в личный кабинет ФИФ ОЕИ
   человеком, затем «Загружен в ЛК ФИФ». Прямой записи по API нет: для
   поверителей запись идёт пакетом через ЛК, для аккредитованных лиц часть —
   через ФГИС Росаккредитации с УКЭП.
4. **Сверка.** Celery beat раз в два часа (и кнопка «Сверить с ФИФ») ищет
   отправленные поверки в открытом реестре (`GET /vri` по номеру типа,
   заводскому номеру и дате) и забирает номер записи. Протокол становится
   «Опубликован в ФИФ». Номер можно внести и руками, как и отказ с причиной.

## Идемпотентность

Частичный уникальный индекс `arshin_item_one_active_per_protocol`: протокол
может быть не более чем в одной строке в состоянии «в пакете», «отправлен»
или «опубликован». Повторно собрать пакет с тем же протоколом нельзя ни из
интерфейса, ни из админки. Отклонённая или отменённая строка протокол
отпускает — он вернётся в очередь и уйдёт следующим пакетом.

## Настройки (.env)

| Переменная | Что это |
|---|---|
| `ARSHIN_SIGN_CIPHER` | Шифр знака поверки организации. Без него пакет не собирается |
| `ARSHIN_XML_NAMESPACE` | Пространство имён схемы. По умолчанию `urn://fgis-arshin.gost.ru/module-verifications/import/2020-06-19` |
| `ARSHIN_BATCH_LIMIT` | Сколько записей максимум в одном файле (1000) |
| `ARSHIN_DEFAULT_PRIMARY` | Экземпляр без прежних поверок считать первичной поверкой (по умолчанию — периодической) |

Вид поверки можно задать явно: `results.verification_kind` = `primary` /
`periodic`.

## Перед первой боевой загрузкой

Росстандарт меняет версии схем. Скачайте действующую XSD из ЛК ФИФ и
проверьте сформированный файл:

```bash
xmllint --noout --schema poverki.xsd arshin-00001.xml
```

Если отличается пространство имён — поменяйте `ARSHIN_XML_NAMESPACE`; если
имена элементов — `result_element()` в `submission.py`, это одна функция.
Имена полей ответа `/vri` при сверке тоже стоит один раз сверить на сервере
(как `fif_probe` для типов).
