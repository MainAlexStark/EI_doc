# Пересборка интерфейса — 21.11.2026

Бэкенд (нумерация, расчёты, Typst, ФИФ, ассистент, логистика) сохраняется и усиливается.
Интерфейс пересобран вокруг **режимов работы**: человек сначала выбирает, чем занят, и
дальше идёт по потоку без лишних экранов.

## Восемь режимов

| # | Режим | Ключ (hash) | Для кого | Суть потока |
|---|---|---|---|---|
| 1 | **Город** | `city` | поверители, диспетчер | Выезды по Кирову и Яранску: адреса дня с окнами 2 ч, счётчики у людей, «забрать коробку» с предприятия (забор → приёмка в лаборатории) |
| 2 | **Командировки** | `trips` | поверители, руководство | Поездка на несколько дней: районы, соседние сёла, адреса по дням, карта, офлайн |
| 3 | **Закупки** | `procurements` | менеджер, руководство; поверитель — чтение | Контракт 44/223-ФЗ: документы (ТЗ, контракт, пропуска), агент читает и вытаскивает требования/перечень СИ/сроки, план-факт по заходам |
| 4 | **Приёмки** | `intake` | все | Клиент принёс коробку: заказчик → приборы списком с клавиатуры/сканера → акт приёма → поверка → выдача |
| 5 | **Сайт** | `/` (публичный) | клиенты | Одностраничник фирмы, форма заявки как можно выше |
| 6 | **Заявки** | `requests` | менеджер, руководство | Разбор входящих на потоке: горячие клавиши, назначение одним касанием |
| 7 | **Шаблоны поверки СИ** | `si-templates` | метролог | Поиск типа в ФИФ → методика → чат с ассистентом рядом с шаблоном → «Продолжить» |
| 8 | **Шаблоны аттестации** | `att-templates` | метролог | План аттестации ИО из документов (ГОСТ Р 8.568) → сверка формул на примере → шаблон протокола |

Вспомогательные разделы: Сегодня (главная), Панель (руководство), Журнал, График, Задачи,
Ассистент, Типы СИ, Сотрудники.

## Дизайн-система v2 «Поверочный стол»

Спокойная точность прибора: светлая рабочая поверхность, один уверенный ультрамарин
(родство с чёрно-синим сайтом), сигнальные цвета только для смысла (годен / непригоден / внимание).

| Токен | Значение | Роль |
|---|---|---|
| `--paper` | `#FAFAFC` | фон |
| `--ink` | `#151821` | текст |
| `--graphite` | `#5C6272` | вторичный текст |
| `--rule` | `#E2E5EC` | линии |
| `--ultramarine` | `#2B45E0` | акцент, действие |
| `--signal` | `#E89B00` | внимание, ждёт |
| `--pass` | `#12925A` | годен, выполнено |
| `--fail` | `#D3311F` | непригоден, отказ |

Шрифты (самохостинг через @fontsource, работают офлайн): **Golos Text** — интерфейс
(кириллица в основе), **JetBrains Mono** — только данные: заводские номера, номера
протоколов, показания (табличные цифры).

Принципы:
- Один главный поток на экране, одно главное действие — всегда в одном месте (справа сверху, на телефоне — снизу).
- Всё делается с клавиатуры: ⌘K / Ctrl+K — палитра команд и поиск по всему; `1…8` — режимы; `N` — новое в текущем режиме; `?` — подсказка клавиш; `Esc` — закрыть.
- Движение отвечает на действие: листы выезжают, строки подтверждаются вспышкой, переход между режимами — View Transitions; `prefers-reduced-motion` уважается.
- Пустой экран — приглашение к действию, ошибка — что случилось и что сделать.
- Скелетоны вместо спиннеров там, где известна форма данных.

## Правила для кода

- Новые общие компоненты — `frontend/src/ui/`; стили режима — свой файл `frontend/src/modes/<mode>/<mode>.css`.
- API режима — `frontend/src/modes/<mode>/api.ts` (общий `api.ts` только для общих вещей).
- Цвета только через токены.

## Оболочка и общие компоненты

Оболочка — `frontend/src/App.tsx`: боковая панель («Сегодня», «Режимы» 1…8, «Работа»,
«Справочники»; сворачивается до иконок, выбор помнится), шапка, таб-бар телефона
(4 режима по роли + «Ещё») и большая кнопка главного действия режима на телефоне.
Адрес — `#/<ключ>[/<хвост>]`; старые `#/field-work`, `#/protocol-templates`, `#/attestations`
перенаправляются. Тёмная тема — по системе или вручную (меню профиля), только для кабинета
(`<html data-app="cabinet">`); публичный сайт остаётся светлым.

### Реестр режимов — `modes/registry.ts`

```ts
type SectionDef = {
  key; title; short; icon; digit?: 1..8; group: "home" | "modes" | "work" | "reference";
  description;                       // одна строка — подзаголовок и строка в «Сегодня»
  visible?: (a: Access) => boolean;  // права: a.isManager / a.isControl / a.isReviewer / a.role
  component?: ComponentType<ModeProps>;   // обычно lazy(() => import("./<key>"))
  href?; flush?; keywords?;
  primary?: { label; icon; action; visible? };  // клавиша N, большая кнопка на телефоне
};
type ModeProps = { me; isManager; isControl; isReviewer; go: Go; refreshCounts: () => void };
type Go = (key: string, opts?: { trip?: number; action?: string; payload?: unknown; sub?: string }) => void;
```

Пересобрать режим = переписать `frontend/src/modes/<key>/index.tsx` (default export, пропсы
`ModeProps`). Сейчас там обёртки над старыми экранами (`Trips mode="city"`,
`Trips only="trips"|"procurements"`, `FieldWork`, `RequestsInbox`, `TemplateStudio`, `Attestations`).
Вспомогательные разделы — `modes/work/*.tsx`. `go("intake", { action: "new" })` — перейти и
сразу попросить режим сделать действие.

### Действия режима — `ui/modeActions.ts`

```ts
useModeAction("intake", { new: () => setCreating(true), "open-order": (id) => open(id as number) });
emitModeAction("intake", "new");        // палитра, клавиша N, кнопка на телефоне, плитка «Сегодня»
```
Если режим ещё грузится, действие ждёт его до 8 с. Имена, которые уже шлёт оболочка:
`city`: `new-visit`, `open-trip`; `trips`: `new-trip`, `open-trip`; `procurements`: `new`,
`new-procurement`, `open-procurement`; `intake`: `new`; `requests`: `open`, `search`;
`journal`: `search`. Новый режим должен их поддержать.

### Тосты — `ui/Toast.tsx`

### Клавиши — `ui/Hotkeys.tsx`

```ts
useHotkey("n", create, { description: "Новая приёмка", group: "Приёмки" });
useHotkey(["j", "arrowdown"], next, { description: "Следующая заявка", group: "Заявки" });
```

`mod` = ⌘/Ctrl; буквы ловятся и в русской раскладке (по `event.code`); в полях ввода и при открытом
окне клавиши без модификаторов молчат. Всё с `description` попадает в справку по «?».
Глобальные: `1…8` — режимы, `N` — главное действие, `?` — справка, ⌘K — палитра.

## Режимы «Сайт» и «Заявки»

**Сайт** (`/o-nas/`, `frontend/src/landing/`; форма — `components/PublicRequestForm.tsx`, также `/zayavka/`).
Одностраничник на тёмном ультрамарине: первый экран — посыл («законная работа начинается с поверки») и форма;
дальше услуги (5 плиток), «без поверки — нельзя», как это работает (заявка → звонок → поверка → ФГИС «Аршин»),
цены из справочника, 5 вопросов, контакты. Реквизиты — `landing/firm.ts` (и JSON-LD в `index.html`).
- Форма: 1 что поверить (кнопки, счётчики первыми; остальное — списком) → 2 адрес (подсказка, стрелки) →
  3 день и окно 2 ч (появляется после выбора приборов) → 4 имя и телефон (маска; email и комментарий — по ссылке).
  Ошибки — у поля (`aria-invalid`, фокус на первую), после отправки — номер заявки, когда позвоним, что дальше.
- ASCII-фон (`AsciiField`): rAF ~30 к/с (сенсорные ~15), пустые кадры в покое, пауза в фоновой вкладке,
  статика при reduced-motion / saveData / слабом железе, без пересчёта при скачках панели адреса.
- SEO: `index.html` — title, description, OpenGraph, schema.org `LocalBusiness`; кабинет меняет title и ставит
  `noindex` (`main.tsx`). Экраны в `main.tsx` грузятся лениво — сайт не тянет кабинет.

**Заявки** (`modes/requests/`: `Inbox.tsx`, `Card.tsx`, `api.ts`, `util.ts`, `requests.css`).
Список (Новые / В работе / Архив, источник, район, поиск) + карточка; телефон — карточка листом.
Клавиши: `J/K` `↓/↑`, `Shift+J/K` — выделять, `Enter`, `A` назначить (AssignPicker: сначала по району, дальше по
загрузке из `/api/dispatch/overview/`), `C` подтвердить (наряд; нет исполнителя — пикер), `X` отклонить с причиной,
`S` спам, `/` поиск, `Esc` снять выделение; Shift/⌘-клик. Всё пачкой — `POST /api/hub/requests/bulk/`.
После действия — следующая заявка; отклонение и спам уходят на сервер через 6,5 с (тост «Отменить»,
при уходе со страницы — сразу, `keepalive`); назначение отменяется возвратом прежнего исполнителя.
Новые заявки — опрос раз в 30 с (подсветка, тост, счётчик). Действия режима: `new` (VisitModal — запись по
телефону, главное действие `N`), `open`, `search`; команды палитры — `requests-mode`.

## Режимы 7 и 8: шаблоны поверки СИ и аттестации ИО

**«Шаблоны поверки СИ»** (`modes/si-templates/`, студия — `assistant/TemplateStudio.tsx`) — пошаговый поток
(`Stepper.tsx`, классы `.flow-steps` — общие для обоих режимов):
1. **Тип СИ** — поиск в ФИФ (`FifTypeSearch`): заведённые типы сверху, изготовитель, предупреждение о совпадающих
   названиях; свой начатый шаблон открывается сразу. Новый тип может завести любой работник — метролог проверит.
2. **Документы** — методика и описание типа из карточки ФИФ (`fetchFifCard` / `fetchSiTypeDocuments`), свои файлы
   (перетащить) и пожелание. Файлы уходят в чат, когда ассистент закончит первый черновик по ФИФ.
3. **Студия** — чат слева, живой протокол справа (PDF / «Состав»); после каждой редакции — полоса «что изменилось»
   и подсветка (добавлено — зелёным, убрано — зачёркнуто). Статус: черновик / на проверке / проверен.
4. **«Продолжить»** (вверху) — лист «Проверка и публикация»: чек-лист (методика, операции, точки, характеристики,
   эталоны, сверка с примером) → «Опубликовать» → метролог «Проверен» → «Создать протоколы» (Приёмки).

Список: поиск, фильтр по статусу, «Ждут вашей проверки: N» для метролога (лист проверки — `ReviewSheet.tsx`).
Клавиши: `N` — новый шаблон, ⌘Enter — отправить / опубликовать / проверен, ⌘S — показать сохранённую редакцию
(черновик сохраняет ассистент), ⌘. — «Протокол ↔ Состав», Esc — к списку.
Действия: `new`, `open-type` (id типа СИ), `open-template` (id шаблона), `open-workspace`; `#/si-templates/<id типа>`.

**«Шаблоны аттестации»** (`modes/att-templates/`) — две вкладки: «Шаблоны по видам ИО» и «Аттестации ИО»
(прежний экран `components/Attestations.tsx`: измерения, расчёт, подпись, протокол — без изменений по сути).
Шаблон = `AttestationProgram` (`/api/attestations/programs/…`). Создание: вид ИО + документы с ролями (пример
протокола / программа / РЭ) → отдельный чат ассистента (`ei_attestation_template_propose`, «Подтвердить») → шаблон
открывается сам; или «из проведённой аттестации» (`save-as-program`). Шаблон: план таблицами (`PlanEditor.tsx`:
общее, точки, режимы, характеристики с формулой/допуском/источником, условия, порядок), вкладка «Сверка с примером»
(`PlanCheckReport`: в примере / посчитано / сходится, расхождения красным), «Для специалиста» — JSON, «Источники».
⌘S — сохранить, метролог — «Проверен», «Применить к новому ИО» → аттестация открывается во второй вкладке.
`PlanEditor` используется и в карточке аттестации (вместо сырого JSON); там же кнопка «Сделать шаблоном».
Действия: `new`, `open-program`, `open-attestation`, `new-attestation`.

Палитра (⌘K): типы СИ по названию/номеру ФИФ, шаблоны поверки, шаблоны аттестации — `modes/si-templates/commands.ts`.
Счётчики в боковой панели: шаблоны поверки и аттестации, ждущие метролога (только проверяющим).

`#/procurements/<id>`: шапка (номер, заказчик/ИНН, контракт, срок, цена, ответственный) и
вкладки (`[` / `]` — соседняя):
- «Выжимка» — блоки `requirements/instruments/stages/access/contacts/penalties/deadline/notes`,
  правятся на месте (`E`, сохранить ⌘↵, тост с «Отменить» возвращает прежнюю).
  «Собрать ассистентом» — лист с чатом встроенного ассистента (`AssistantSheet`, как в
  TemplateStudio) и готовым заданием на `ei_procurement_documents/_search/_summary_propose`;
  запись — карточкой «Подтвердить», после закрытия выжимка перечитывается.
- «Документы» — состояние чтения (опрос, пока «читается»), поиск по всем документам со
  сниппетами → просмотр текста с подсветкой у найденного места, загрузка (и перетаскиванием),
  «прочитать заново», скачать, удалить.
- «Пропуска» — `PassModal` из `components/Procurements.tsx`; объекты заказчика.
- «Заходы» — командировки по закупке (открываются в «Командировках»), «Спланировать заходы»:
  предпросмотр `visit-plan` (приборов в день, дней в заходе, старт, старший, кто едет) → «Применить».
Права — с сервера (`can_edit`): поверитель видит закупки своих командировок только на чтение.
Действия: `new`, `new-procurement`, `open-procurement`, `list`.

**Приёмки** — `modes/intake/`. Доска по стадиям приём → поверка → готов к выдаче → выдан
(стадия считается из поверок, `stageOf`); «Выдано» и «Вернуть в работу» с «Отменить»,
акты, ответственный прямо в карточке (руководство, тост с отменой), «Вернуть с доставкой»
(`POST /api/orders/{id}/delivery/`), метки «с выезда» / «доставка» (`pickup`/`delivery` наряда).
«Новая приёмка» (`N`) — один лист: заказчик (недавние сверху, поиск по названию/ИНН, «Физлицо»)
→ кто сдал/телефон/закупка/ответственный → `FastTable`: тип с автодополнением по справочнику
(новая строка берёт тип предыдущей, последний помнится — `ei_doc_intake_last_type`), заводской №,
год; Enter — следующая строка (сканер = ввод + Enter), ↑/↓ по столбцу, вставка столбца или
«тип ⇥ номер ⇥ год» из Excel, подсказка «уже поверяли — прошлая поверка …» по своей базе.
Сохраняется пачкой (`/instruments/bulk/`, `client_id` строки — повтор безопасен) → «Акт приёма».
Карточка — **`#/intake/<id>`** (id наряда-приёмки; так ссылаются «Город» и агент, через оболочку —
`go("intake", { sub: String(id), action: "open-order", payload: id })`): прежний экран ввода
измерений/протоколов (`FieldWork` на одном наряде) + «Таблицей» (`T`) и «С доставкой».
Палитра: `modes/intake/commands.ts` — приёмки по заказчику/ИНН/№ и по заводскому № (в истории
прибора теперь `last.work_order_id`). Адрес карточки обоих режимов — `modes/procurements/hash.ts`
(`useHashId`).
