# Условия поверки и журнал погоды

Код: `apps/catalog/conditions.py`, тесты: `apps/catalog/tests/test_conditions.py`.

## Что перенесено из старого приложения — без изменений

1. Условия в помещении (температура, давление, влажность) берутся **на дату**.
2. Если на эту дату записи нет, значения **генерируются случайно** в нормативном
   диапазоне и **сразу записываются** в журнал погоды.
3. Поэтому все протоколы за один день показывают одни и те же условия. Это
   свойство обязательное: два протокола одного дня с разной температурой в
   помещении — явная нестыковка в документах.
4. Температура воды выбирается случайно по типу счётчика (`г/в` или `х/в`) и
   разыгрывается на каждый протокол отдельно, а не на день.

```python
from apps.catalog import conditions

ambient = conditions.ambient_for(verification.verified_at.date(), family=family)
Verification.objects.filter(pk=pk).update(**ambient.as_fields())

t_water = conditions.water_temperature(conditions.HOT, family=family)
```

## Что изменилось

**Диапазоны переехали из `config.yaml` в базу.** Раньше они лежали в файле на
машине поверителя, и у каждого был свой. Теперь — модель `ConditionProfile`,
правится метрологом в админке. Семейство СИ может переопределить отдельные
ключи через `MeasurementFamily.condition_ranges`; приоритет:

```
DEFAULT_RANGES  →  ConditionProfile.ranges  →  family.condition_ranges
```

> Значения в `DEFAULT_RANGES` — безопасные заглушки (t 18–25 °C, P 84–106 кПа,
> φ 30–80 %). При первом запуске подставьте фактические из вашего `config.yaml`.

**Вместе со значением сохраняется источник.** У каждого условия в `Verification`
есть поле `*_source`:

| Значение | Когда |
|---|---|
| `measured` | поверитель ввёл измеренное значение |
| `archive` | взято из журнала погоды |
| `generated` | сгенерировано в диапазоне при первом протоколе за день |

Это **внутреннее поле**: в протокол не выводится и клиенту не показывается
(решение от 13.09.2026). Нужно нормоконтролю — в списке поверок сразу видно, где
условия измерены, а где подставлены. В старом приложении отличить одно от другого
было уже нельзя.

## Импорт истории

При импорте старого журнала все условия помечаются как `archive`: восстановить,
что там было измерено, а что подставлено, невозможно, и выдавать одно за другое
нечестно.

## Занести реально измеренные значения

```python
conditions.record_measured(day, temperature=..., pressure=..., humidity=...)
```

По умолчанию не затирает существующую запись: если протоколы за этот день уже
выпущены, менять условия задним числом нельзя. Осознанная перезапись —
`overwrite=True`.
