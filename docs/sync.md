# Синхронизация с полевыми устройствами

Код: `backend/apps/sync/` (`auth.py`, `api.py`), на телефоне —
`frontend/src/offline/sync.ts`.

## Вход и отзыв

- Сотрудник входит через `POST /api/auth/device-token/` с постоянным
  `device_id` браузера/телефона. Устройство регистрируется за сотрудником
  (`core.Device`), refresh-токен живёт **30 дней**, в токенах записан
  `device_id`. Учётная запись без карточки сотрудника входит по-обычному
  (`/api/auth/token/`, refresh 7 дней).
- **Отзыв:** в админке «Устройства» → «отозвано». С этой секунды
  отказывают и access (`DeviceJWTAuthentication`), и обновление пары, и
  повторный вход с этого устройства. Устройство, закреплённое за одним
  сотрудником, не принимает вход другого.

## Данные

- **С сервера — дельта по курсору:** `GET /api/sync/pull/?cursor=<мс>`
  отдаёт изменённые наряды (свои; диспетчеру — все), поверки по ним,
  остановки командировок и новый курсор. Первый раз — открытые наряды и
  закрытые за неделю. Курсор берётся с запасом 5 с назад, клиент делает
  upsert, поэтому перекрытие безопасно; больше 500 строк — `more: true`,
  клиент дочитывает.
- **На сервер — очередь (outbox):** прежние идемпотентные операции по
  `client_id` (UUID с телефона). Повтор не создаёт дубль.
- **Конфликты:** «последний пишет» по полю; неотправленная локальная поверка
  не затирается серверной копией; измерения подписанного протокола сервер
  не принимает никогда.
- **Без связи на старте:** профиль, наряды и поверки берутся из телефона
  (IndexedDB), экран «Поверки» работает.
