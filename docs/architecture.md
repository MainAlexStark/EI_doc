# Архитектура EI_doc

Версия 0.2 · 13.09.2026

Заменяем EI_protocols (PyQt6 + Excel COM, только Windows) и поглощаем EI_HUB
(Django 4.2 + DRF + SimpleJWT + PostgreSQL).

## Принципы

1. **Истина в базе.** PDF, Excel, Word — производные, перегенерируемые из данных.
2. **Расчёт — это код** с тестами, а не формула в ячейке.
3. **Подписанное неизменно.** Правка = новая версия со ссылкой на предыдущую.
4. **Офлайн — норма,** а не сбой.
5. **Один сервер,** один `docker compose up`.

## Диагноз старой системы

| Что было | Во что упиралось |
|---|---|
| Журнал — файл `.xlsx`, доступ по индексам столбцов (`values[32]`, `row[47]`) | Сдвиг столбца ломает всё молча; `workbook.save()` перезаписывает файл целиком → при двух пользователях теряются данные |
| Генерация через `win32com` | Только Windows, один процесс Excel, последовательно |
| Расчёты в формулах `.xlsm`; Q наиб вычитывается из `AC53:AC55` сохранённого файла | Самое хрупкое место: правка шаблона метрологом ломает код |
| Условия поверки при отсутствии генерировались `random.uniform` | Происхождение числа в протоколе система не помнит |
| Пути, табельные номера, ключи — в `config.yaml` на машине пользователя | У каждого свой конфиг и свой журнал |

Отдельно: `.env` с `SECRET_KEY` и паролем БД закоммичен в репозиторий EI_HUB —
ротировать и вычистить из истории.

## Стек

Python 3.12 · Django 5 + DRF + SimpleJWT · PostgreSQL 16 (PostGIS с этапа 4) ·
Celery + Redis · **Typst** для PDF · xlsxwriter / docxtpl для файловых выгрузок ·
React + TS + Vite PWA · Dexie (IndexedDB) + Workbox · MapLibre + OSM ·
OSRM + OR-Tools · Telegram-бот для уведомлений.

Приложения: `core`, `catalog`, `verification`, `hub`, `tasks`, `logistics`,
`sync`, `arshin` — каталоги внутри одного процесса, а не сервисы.

## Доменная модель

Журнал учёта — **не сущность**, а представление над `Verification` с экспортом
в Excel.

- **НСИ:** `MeasurementFamily`, `SiType`, `Standard`, `VerificationMethod`,
  `ProtocolTemplate` (версионируется), `Employee` + `Attestation` со сроком.
- **Работа:** `Client`, `Site`, `Instrument` (живёт между поверками),
  `Verification` (центральная), `Protocol`, `NumberingScope`.
- **Измерения** — JSONB по схеме семейства, а не 50 колонок на все случаи.
- **Аудит** — `django-simple-history` по ключевым моделям.
- **Условия поверки** — журнал погоды на дату с генерацией недостающих значений,
  как в старом приложении; источник значения (измерено / из журнала /
  сгенерировано) сохраняется, но остаётся внутренним полем. См.
  [docs/conditions.md](conditions.md).

## Нумерация протоколов

Формат `ЕИ-03-02-00772`, счётчик сбрасывается 1 января. Требование метролога:
номера идут строго по времени поверки, при этом поверки приходят не по порядку
и правятся задним числом.

Решение — разделение на запечатанную зону и пересчитываемый хвост.
Подробно: **[docs/numbering.md](numbering.md)**. Код: `apps/verification/numbering.py`.

## Реестр ФИФ на входе

При заведении СИ поверитель вводит номер в Госреестре или часть названия, а
система показывает варианты **с изготовителем**: `GET /api/catalog/si-types/suggest`.
Сначала типы, уже заведённые в системе, затем кандидаты из открытого реестра.
Совпадающие наименования помечаются как неоднозначные — счётчики с одним названием
от разных производителей были частой причиной ошибок. Реестр недоступен —
локальные варианты всё равно отдаются, с предупреждением: заведение СИ не блокируется.

## Роли

Владелец · Руководитель · Метролог/нормоконтроль · Менеджер · Поверитель ·
Наблюдатель. Django Groups + объектные правила (`django-rules`).
Право подписи — доменное правило (действующая аттестация), не галочка в UI.
Полевые устройства: refresh 30 дней с привязкой к `device_id`, отзыв из админки.

## EI_Hub

Переезжает внутрь как `apps.hub`, одна БД. Формы сайта → `Request`
(`AnonRateThrottle` 20/час + капча). Путь: форма → авто-роутинг по району →
подтверждение → наряд → поверка → закрытие и выгрузка в ФИФ.

## Документы

`Verification` → Calculator (чистые функции) → RenderContext → Typst → PDF + SHA-256.

Миграция формул: выгрузить карту формул через `openpyxl(data_only=False)` →
переписать в Python → **золотые тесты на 100–200 уже выпущенных протоколах** →
только потом отключать Excel.

Excel и Word остаются на импорт (по заголовкам), экспорт (с нуля) и договоры
(`docxtpl`). Подпись: сначала графическая, потом УКЭП.

## Офлайн

Дельта-синхронизация по курсору; outbox с `client_id` (UUIDv7), сервер
идемпотентен; конфликты — LWW по полю в черновике, подписанный протокол не
перезаписывается никогда; вложения отдельной очередью с докачкой; тайлы карты
предзагружаются на район командировки.

Оцифровка бумаги: бланк печатается из системы с QR и реперными метками →
выравнивание OpenCV → VLM с жёсткой JSON-схемой → **обязательный экран сверки**.

## Командировки

Планирование от накопленного спроса (заявки + истекающие МПИ по географии),
резервирование эталонов, PDF-пакет на выезд, план/факт по рейсу.
Город: геокодирование, кластеризация с временными окнами, VRP через OR-Tools + OSRM.

## Аршин

Чтение — публичный API ФИФ ОЕИ, кэшируется. Запись — пакетный XML через ЛК ФИФ,
для аккредитованных лиц часть через ФГИС Росаккредитации с УКЭП; требования
сверить с действующими документами Росстандарта перед реализацией.
Всё изолировано в `apps.arshin` + `ArshinSubmission` (идемпотентность, ретраи).

## Инфраструктура

Один VPS 4 vCPU / 8 ГБ / 100 ГБ. Контейнеры: web, worker, beat, postgres, redis,
osrm (с этапа 4) — и общий Caddy на машину вместо своего nginx: тот же
`/opt/infrastructure`, та же `mcp-network`, что у MCP-серверов (`ozon-seller-mcp`,
`k8s-mcp`), один Caddyfile на все сервисы этого VPS. Разворачивается и
обновляется `./deploy.sh` по тому же стандарту (маркеры `# >>> ei-doc` /
`# <<< ei-doc` в общем Caddyfile, здоровье через `/healthz`, откат при неудачном
обновлении). Статику отдаёт whitenoise прямо из процесса Django (общий Caddy
файлы не отдаёт, только TLS и роутинг), защищённые файлы — `django-sendfile2`
вместо прежнего `X-Accel-Redirect` (тот был завязан на nginx). Фронтенд журнала
(React) собирается отдельной стадией того же `docker build` и отдаётся тем же
процессом Django (`STATICFILES_DIRS`, `apps.core.views.frontend_index`) — своего
сервиса под него нет. Бэкапы: `pg_dump`
+ WAL, `restic` в объектное хранилище, проверка восстановления раз в квартал.
152-ФЗ закрыть до запуска.
