# Ассистент-метролог (16.10.2026)

Вкладка «Ассистент» — чат с LLM в духе OpenRouter Chat, встроенный в EI_doc: агент ищет во ФГИС «Аршин»
(через RSTMetrology_MCP), в методиках и внутренних файлах компании, в интернете; читает и создаёт Word/Excel/PDF;
показывает виджеты; составляет черновики протоколов по образцу; заводит типы СИ — через кнопку подтверждения.
Код: `backend/apps/assistant`, `frontend/src/assistant`.

## Решения (с Алексом)
- **LLM:** OpenRouter + Yandex AI Studio через один OpenAI-совместимый клиент. Модель — «провайдер:модель»
  (`openrouter:anthropic/claude-sonnet-4.5`, `yandex:qwen3-235b-a22b-fp8/latest`), выбор в чате как в OpenRouter
  (поиск по каталогу, контекст, цена, 👁 — видит картинки, избранное). Каталог OpenRouter — только модели с `tools`.
- **Веб-поиск:** Yandex Search API v2 (тот же каталог/ключ Yandex Cloud, роль `search-api.webSearch.user`)
  + `web_fetch` — чтение HTML/PDF/DOCX по ссылке (описания типов и методики на fgis.gost.ru — PDF).
- **Запись в данные компании — только по кнопке.** Агент готовит `PendingAction` (карточка с данными и
  источниками), выполняется от имени нажавшего, с его правами. Тип, заведённый поверителем, как и раньше
  `needs_review` — протокол не подпишется до проверки метролога.

## Как устроено
- `Conversation` / `Message` — история в формате OpenAI (user / assistant+tool_calls / tool / event). `Message.ui` —
  только для человека: виджеты, источники, файлы, карточка действия.
- `Run` — прогон агента в Celery, очередь `assistant`, отдельный контейнер `assistant-worker` (в `mcp-network`,
  чтобы ходить к RSTMetrology_MCP по имени контейнера). Готовые сообщения пишутся в БД, недописанный текст —
  в Redis; экран опрашивает `GET /api/assistant/runs/<id>/?after=` каждые 0,6 с (без SSE — gunicorn sync-воркеры
  и Caddy не держат долгих соединений). Остановка — `cancelling`, проверяется раз в секунду. Прогон, висящий
  дольше 30 минут (умер воркер), помечается ошибкой при открытии чата.
- Цикл (`agent.py`): до `max_steps` (по умолчанию 30) шагов модель → инструменты; на последнем шаге инструменты
  отключаются и модель обязана подвести итог. Ошибка инструмента уходит модели текстом («Ошибка: …») — она
  исправляет аргументы. Результат инструмента обрезается до 30 000 символов.
- Картинки из чата уходят в модель как `image_url` (JPEG ≤1600 px), только если модель их видит; иначе — пометка.
  Текст файлов до 12 000 символов вставляется прямо в сообщение, длиннее — `attachment_read` по частям.

## Инструменты агента
`context_search` / `context_read` (файлы компании), `memory_save` / `memory_delete`, `web_search` / `web_fetch`,
`attachment_read`, `file_create` (docx/pdf из блоков, xlsx/csv из листов, md/txt), `protocol_draft`
(Word + PDF с водяным знаком ЧЕРНОВИК + обязательная таблица происхождения каждого значения: confirmed / derived /
missing — без источника инструмент отказывает), `ei_si_types`, `ei_si_type_propose`, `ei_journal`,
`ei_reference` (семейства, эталоны со сроками, методики, сотрудники), `ui_show` (виджеты), + все инструменты
включённых MCP-серверов как `mcp__<имя>__<инструмент>`.

Документы (`documents.py`): блоки heading / paragraph / fields (строки «подпись — значение» с подчёркиванием и
мелкой подписью, как в бланках протоколов) / table / list / signatures / pagebreak → .docx (python-docx) и PDF
(Typst, `typst/document_v1.typ`, тот же `render_pdf`, что у протоколов поверки).

Виджеты: table (сортировка, фильтр, копирование для Excel), cards (кнопка «Выбрать» отправляет выбор в чат),
kv, chart (bar/line, SVG), steps, choices, callout, compare, facts, html (песочница iframe `allow-scripts`).

## Системный промт (`prompt.py`)
Главное — «ошибки недопустимы»: ничего конкретного из памяти модели; у каждого значения статус ✅ / 🔎 / ❓;
тип СИ установлен только по номеру реестра + изготовителю (+ модификации), иначе — карточки и выбор человека;
пустое поле лучше неверного. Иерархия источников: ФГИС → описание типа/методика → файлы компании → сайты
изготовителей → прочее. Отдельный раздел — поиск по неполным данным без подсказок: прямой поиск по
изготовителю → история поверок → «соседи» (приборы одного владельца поверяют одной партией в один день одним
поверителем: найти поверки известных соседей, затем записи того же поверителя за ту же дату) → подтверждение
двумя независимыми признаками → описание цепочки в ответе. Плюс порядок заведения типа СИ и составления
протокола (эталоны — из справочника, их свидетельства — найти во ФГИС и проверить срок на дату протокола;
результаты измерений — только от человека).
К промту каждый раз добавляются: дата и пользователь, правила компании из настроек, память (общая + личная),
файлы «Всегда» целиком (в пределах бюджета), оглавление файлов «Поиск», предупреждение, если ФГИС недоступна.

## Контекст (панель справа)
- **Файлы:** разделы (правила, методики, описания типов, эталоны, образцы протоколов, нормативка, прочее), общие
  (загружает метролог/руководитель/владелец) и личные. Режим у каждого файла: «Всегда» / «Поиск» / «Выкл»,
  полоса бюджета «Всегда» в токенах, превью текста, описание («о чём файл» — агент по нему решает, открыть ли),
  «Проверить, что агент найдёт» — тот же поиск, что у агента. Поиск — полнотекстовый PostgreSQL `russian`
  + бонус за точное вхождение номеров («МИ 1592», «16078-05»). PDF без текстового слоя честно помечается.
- **Память:** общая (меняет метролог; агент предлагает через карточку) и личная (агент пишет сразу).
- **Инструменты:** MCP-серверы со статусом связи и включением/выключением отдельных инструментов, встроенные.
- **Настройки:** модель по умолчанию, правила компании для ассистента, шагов на ответ, бюджет «Всегда», расход.

## Настройка (.env, `./deploy.sh` спрашивает сам)
`OPENROUTER_API_KEY`, `ASSISTANT_DEFAULT_MODEL`, `ASSISTANT_YANDEX_MODELS`, `ASSISTANT_PUBLIC_URL`,
`RST_MCP_URL` (+ `RST_MCP_TOKEN` — статический токен чтения RSTMetrology_MCP, `--gen-token` → `<P>_TOKEN_READ`),
`YANDEX_SEARCH_API_KEY` (необязательно). RST-сервер заводится сам при `migrate`; другие MCP — в панели.

## Не сделано / дальше

- Нет семантического (векторного) поиска — при тысячах файлов добавить pgvector.

- Нет стриминга по SSE — опрос раз в 0,6 с; при росте числа пользователей — перейти на SSE через gthread/ASGI.
